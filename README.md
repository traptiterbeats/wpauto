# wpauto

پنل نصب خودکار وردپرس روی هاست‌های cPanel، نوشته‌شده با Go.

## نصب (Ubuntu 22.04 / 24.04، با دسترسی root)

```bash
bash <(curl -Ls https://raw.githubusercontent.com/traptiterbeats/wpauto/main/install.sh)
```

نصب‌کننده پورت پنل را می‌پرسد، نام کاربری و رمز تصادفی می‌سازد و آدرس پنل را نشان می‌دهد.

## مدیریت

```bash
wpauto            # منوی مدیریت
wpauto info       # آدرس پنل و وضعیت
wpauto update          # نصب آخرین نسخه‌ی پایدار (هیچ‌وقت نسخه‌ی بتا نمی‌گیرد)
wpauto update --beta   # نصب تازه‌ترین نسخه، بتاها (مثل v0.15.0-beta.1) هم حساب
```

### نسخه‌ی بتا

گزینه‌ی `--beta` فقط در نسخه‌های بتا هست؛ بار اول با نصب‌کننده بروید روی بتا (تنظیمات و داده‌ها می‌مانند):

```bash
bash <(curl -Ls https://raw.githubusercontent.com/traptiterbeats/wpauto/ui-minimal/install.sh) --beta
```

برگشت به نسخه‌ی پایدار: `wpauto update` (آخرین نسخه‌ی پایدار را نصب می‌کند).

منو شامل: تغییر نام کاربری و رمز، تغییر پورت، SSL (Let's Encrypt یا self-signed)، استارت/استاپ/ری‌استارت، لاگ‌ها، آپدیت و حذف.

### بخش‌های ادمین

«مدیریت قالب‌ها (ادمین)» (افزودن/حذف قالب و دمو، کتابخانه‌ی افزونه‌ها؛ مشترک بین همه‌ی پروژه‌ها) فعلاً برای کاربر واردشده‌ی پنل باز است.
برای پنهان کردنش در `/etc/wpauto/config.json` بگذارید `"admin_ui": false` و سرویس را ری‌استارت کنید (`systemctl restart wpauto`)؛
کارت و لینک‌ها پنهان می‌شوند و آدرس‌هایش پاسخ ۴۰۳ می‌دهند. حذف این کلید یا `true` آن را برمی‌گرداند.

**افزونه‌های همراه قالب:** افزونه‌های اختصاصی قالب که در wordpress.org نیستند (مثل `electromart-core`) و درون‌ریز دموی سایه را
در فرم «افزودن قالب»، فیلد «افزونه‌های همراه قالب (zip، اختیاری)» همراه قالب و دمو بارگذاری کنید (چند فایل با هم). این zipها در کتابخانه‌ی افزونه‌ها هم ذخیره می‌شوند
و افزونه‌هایی که دمو لازم دارد، اگر zipشان در کتابخانه باشد از کتابخانه نصب می‌شوند و گرنه از wordpress.org. اگر افزودن قالب خطا بدهد، چیزی به کتابخانه اضافه نمی‌شود.
موقع نصب، هر افزونه‌ای که zipش در کتابخانه باشد از کتابخانه نصب می‌شود؛ پس برای قالبی که قبلاً بدون افزونه‌ی همراهش اضافه شده، کافی است zip آن را در کتابخانه بارگذاری کنید.
روی کارت قالب، هر افزونه برچسب «کتابخانه»، «wp.org» یا (اگر zip لازمش در کتابخانه نیست) «⚠ zip ندارد» دارد.

## پروفایل هاست

هر خانواده از هاست‌های cPanel یک فایل YAML کوچک دارد (پورت، روش ورود، نسخه‌ی PHP پیشنهادی، بررسی‌ها و ویژگی‌های خاص). موتور برای همه یکی است.
پروفایل‌های داخلی: `generic` و `autopilo`. برای هاست جدید، [generic.yaml](internal/profile/builtin/generic.yaml) را در `/etc/wpauto/profiles/<id>.yaml` کپی و ویرایش کنید؛ بدون ری‌استارت در فرم افزودن هاست ظاهر می‌شود.

رمز هاست‌ها با AES-256-GCM در `/etc/wpauto/hosts.json` ذخیره می‌شود و کلیدش در `/etc/wpauto/secret.key` است. بعد از یک ورود ناموفق، تلاش خودکار متوقف می‌شود تا فایروال هاست (CSF/cPHulk) IP سرور را بلاک نکند.

## کارها (Workflow)

هر کار یک فایل YAML است: ورودی‌های فرم و مراحل پشت‌سرهم. هر مرحله یکی از «نوع مرحله»های داخلی را اجرا می‌کند و خروجی‌اش با `{{.Steps.<id>.<key>}}` در مراحل بعد قابل استفاده است. ورودی‌ها با `{{.Inputs.<name>}}`.

```yaml
id: wp-check-domain
title: بررسی وردپرس دامنه
inputs:
  - {name: domain, label: دامنه, type: domain, required: true}
steps:
  - {id: login,  title: ورود,  uses: cpanel.login}
  - {id: detect, title: بررسی, uses: wp.detect, with: {domain: "{{.Inputs.domain}}"}}
```

نوع‌های مرحله: `cpanel.login`، `cpanel.preflight`، `cpanel.uapi` (فقط خواندنی)، `cpanel.subdomain`، `cpanel.mkdir`، `cpanel.php`، `cpanel.autossl`، `mysql.create`، `wp.detect`، `wp.plan`، `wp.helper`، `wp.files`، `wp.config`، `wp.setup`، `wp.health`، `log`.

### نصب وردپرس
کار «نصب وردپرس» روی ساب‌دامین (پیشنهادی) یا پوشه‌ی جدا نصب می‌کند و هرگز روی پوشه‌ی غیرخالی یا وردپرس موجود نمی‌نویسد. مراحل: بررسی مقصد → ساخت ساب‌دامین/پوشه → PHP ترجیحی پروفایل → درخواست AutoSSL → دیتابیس و کاربر با رمز تصادفی → یک فایل PHP موقت با توکن تصادفی → دانلود وردپرس روی خود هاست (اگر نشد، پنل دانلود و آپلود می‌کند) → wp-config با کلیدهای تازه → نصب و ساخت مدیر → .htaccess → تست سلامت → حذف فایل موقت.
اگر مرحله‌ای خطا بدهد، دیتابیس، کاربر، ساب‌دامین و پوشه‌ای که همین اجرا ساخته برگردانده می‌شوند. رمزها در لاگ و تاریخچه ذخیره نمی‌شوند.
کارهای سفارشی را در `/etc/wpauto/workflows/*.yaml` بگذارید. هر هاست هم‌زمان فقط یک کار اجرا می‌کند، لاگ زنده در مرورگر دیده می‌شود و تاریخچه در `/etc/wpauto/runs` می‌ماند.

### نصب قالب و دمو

۱. در صفحه‌ی «قالب‌ها»، zip افزونه‌ی «درون‌ریز دمو سایه» را در کتابخانه‌ی افزونه‌ها بارگذاری کنید (یک بار).
۲. zip قالب و (اختیاری) بسته‌ی دموی سایه‌ی آن را اضافه کنید. افزونه‌هایی که `demo.json` لازم دارد (مثل ووکامرس) خودکار از wordpress.org اضافه می‌شوند؛ افزونه‌های اختصاصی را در کتابخانه بگذارید.
۳. کار «نصب قالب و دمو» را روی هر وردپرس موجود اجرا کنید (دامنه + پوشه‌ی اختیاری).

ترتیب: افزونه‌ها ← قالب ← فعال‌سازی ← بسته‌ی دمو در `uploads/sdi-packages` ← مراحل درون‌ریز سایه یکی‌یکی (هر مرحله یک درخواست، مناسب هاست اشتراکی) ← تست سلامت.
چیزی که از قبل روی سایت هست بازنویسی نمی‌شود. اگر کاری خطا بدهد، محتوای دمو با حذف‌کننده‌ی خود سایه پاک می‌شود، قالب قبلی برمی‌گردد و قالب و افزونه‌های تازه حذف می‌شوند.

### شخصی‌سازی دمو برای مشتری

۱. در «هوش مصنوعی» یک سرویس اضافه و تست کنید: OpenAI، Google Gemini، OpenRouter یا هر سرویس سازگار با OpenAI (آدرس API + مدل + کلید). کلیدها با AES-256 روی سرور می‌مانند.
۲. در «شخصی‌سازی» برای یک قالب دمودار پیش‌نویس بسازید: بریف مشتری، لوگو و تصاویر (هر جا خالی بماند تصویر دمو می‌ماند).
۳. «نوشتن متن‌ها با هوش مصنوعی» را بزنید، متن‌ها را ببینید و هر جا لازم بود دستی اصلاح کنید.
۴. «نصب روی سایت» همان کار «نصب قالب و دمو» را با این پیش‌نویس باز می‌کند؛ بسته‌ی دموی ساخته‌شده به‌جای دموی اصلی درون‌ریزی می‌شود.

قالب‌ها با [قرارداد شخصی‌سازی](docs/customize-contract.md) آماده می‌شوند: متن‌ها در Customizer، لوگو و رنگ اصلی، و فایل `customize.json` که هر متن را به یک نقش مشترک (مثل `hero.title` یا `contact.email`) وصل می‌کند. بدون آن، متن‌ها خودکار از `demo.json` پیدا می‌شوند. نمونه‌ی کوتاه:

```json
{"version":1,
 "fields":[{"path":"theme_mods.hero_title","label":"تیتر اصلی","kind":"short","hint":"حداکثر ۶ کلمه"},
           {"path":"posts[slug=about].content","label":"درباره ما","kind":"html"},
           {"path":"theme_mods.contact_email","label":"ایمیل","role":"contact.email"}],
 "auto":false,
 "logo":{"theme_mod":"custom_logo","label":"لوگو"},
 "images":[{"id":"hero","label":"تصویر بالای صفحه"}]}
```

در قرارداد نسخه‌ی ۲ هر جای تصویر نسبت استاندارد (16:9، 4:3، 1:1، 3:4)، اندازه‌ی خروجی، اولویت و گروه (`site` یا `products`) دارد؛ عکس‌های مشتری (هر تعداد، هر اندازه) خودکار به نزدیک‌ترین جای خالی می‌روند، از وسط برش و تغییر اندازه می‌خورند و WebP می‌شوند. قالبی که `"products"` اعلام کند در هر اجرا دو گزینه دارد: «محصولات دمو بمانند» یا «هوش مصنوعی محصولات نمونه بسازد». جزئیات در [قرارداد شخصی‌سازی](docs/customize-contract.md).

### AutoPilot — ساخت خودکار سایت

منوی «AutoPilot» یک فرم دارد: هاست، دامنه و محل نصب (ساب‌دامین / پوشه / خود دامنه؛ نام خالی = خود دامنه)، عنوان و زبان، مدیر وردپرس، قالب (از کاتالوگ، فقط قالب‌های دمودار)، سرویس هوش مصنوعی و بریف مشتری (توضیح آزاد، نام، حوزه‌ی کار، تماس، شبکه‌ها، رنگ‌ها، لوگو)، عکس‌های مشتری (هر تعداد) و — اگر قالب محصول داشته باشد — حالت محصولات. با «شروع» یک پروژه ساخته (یا پروژه‌ی فعالِ همان سایت استفاده) می‌شود و این مرحله‌ها پشت سر هم اجرا می‌شوند:

1. **شخصی‌سازی با هوش مصنوعی** — هنوز چیزی روی هاست تغییر نمی‌کند. تا ۳ تلاش (با فاصله‌ی ۳۰ و ۶۰ ثانیه)، هر بار فقط متن‌های جامانده. اگر هر ۳ تلاش ناموفق باشد کار می‌ایستد و لینک پیش‌نویس نشان داده می‌شود.
2. **نصب وردپرس** — همان کار «نصب وردپرس» با برگرداندن تغییرات در صورت خطا.
3. **نصب قالب و دموی شخصی‌سازی‌شده** — بسته‌ی دموی مشتری ساخته، آپلود و با درون‌ریز سایه وارد می‌شود.
4. **بررسی سایت** — صفحه‌ی اصلی باید HTTP 200 بدهد (با چند تلاش برای 503)؛ فعال بودن قالب و باقی ماندن متن‌های دمو فقط هشدار است.

بررسی هاست و بررسی وردپرس انجام نمی‌شود. صفحه‌ی پیشرفت زمان کل و زمان هر مرحله را نشان می‌دهد، دکمه‌ی توقف و «ادامه از همین مرحله» دارد و وضعیت در `autopilot/` پوشه‌ی تنظیمات ذخیره می‌شود (بدون رمز). رمز مدیر فقط در حافظه می‌ماند؛ اگر پنل وسط کار دوباره راه‌اندازی شود، AutoPilot «قطع شد» علامت می‌خورد و برای ادامه رمز دوباره پرسیده می‌شود.
